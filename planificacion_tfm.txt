
El paper original:
- Usa 50 imágenes de cromosomas de 512x512 píxeles con sus anotaciones YOLO
- Aplica 17 operadores de preprocesado (binarización Otsu/Spline + filtros morfológicos opening/closing en tamaños 2x2 a 5x5)
- Entrena un YOLOv8x separado por cada operador
- Combina predicciones con un ensemble y función de consenso
- La métrica base es el operador "No operation" (YOLO sobre imágenes originales sin preprocesado)

La CONTRIBUCIÓN DEL TFM es añadir modelos de difusión como operador adicional de mejora de imagen
y comparar si mejoran el rendimiento de YOLO respecto al "No operation" del paper.


## 2. DATASET

- 50 imágenes de cromosomas en metafase, 512x512 píxeles
- Ya tienen anotaciones en formato YOLO (.txt con bounding boxes)
- Tarea: detección de cromosomas dicéntricos (bounding boxes)
- Split: seguir el mismo esquema de k-fold que el paper (5-fold cross validation)
- Hardware: RTX 5060 8GB local

## 3. PIPELINE COMPLETO DEL TFG

FASE A — Baseline YOLO (replicar "No operation" del paper):
  1. Split 5-fold de las 50 imágenes
  2. Entrenar YOLOv8 (nano o small, no x — dataset muy pequeño) en cada fold
  3. Evaluar en test: métricas mAP@50 y mAP@50:95
  4. Estas métricas son el BASELINE comparable al "No operation" del paper

FASE B — Modelos de difusión (contribución propia):
  1. Aplicar StableSR con distintas configuraciones a las imágenes
  2. Evaluar calidad de imagen mejorada (BRISQUE, NIQE, SSIM, PSNR)
  3. Elegir mejor configuración
  4. Pasar imágenes mejoradas por YOLO (mismo modelo ya entrenado, sin reentrenar)
  5. Comparar mAP antes vs después → conclusión principal del TFG

NOTA IMPORTANTE: El modelo de difusión NO se reentrena para cada fold de YOLO.
Se entrena/configura una vez y se aplica como preprocesado al test set.

## 4. MODELO DE DIFUSIÓN ELEGIDO: StableSR

Paper: "Exploiting Diffusion Prior for Real-World Image Super-Resolution" (IJCV 2024)
Repositorio: https://github.com/IceClear/StableSR

Por qué StableSR:
- Diseñado específicamente para super-resolución blind (sin conocer la degradación)
- No requiere pares imagen degradada/nítida para inferencia básica
- Tiene módulos entrenables ligeros (no requiere entrenar la UNet completa)
- Disponible en HuggingFace


---

## 5. ARQUITECTURA DE STABLESR (importante para entender qué se puede modificar)

Componentes:
- UNet de Stable Diffusion → CONGELADA (860M parámetros, no se toca)
- Time-aware Encoder → ENTRENABLE (recibe imagen degradada, inyecta features en UNet)
- CFW Module (Controllable Feature Wrapping) → ENTRENABLE (balancea fidelidad vs calidad)

Por qué la UNet está congelada:
- Fue entrenada con millones de imágenes, contiene el prior de "imagen nítida"
- Descongelarla con 50 imágenes causaría catastrophic forgetting
- No cabe en 8GB de VRAM entrenar la UNet completa

El parámetro dec_w controla el CFW en inferencia:
- dec_w = 0.0 → máxima creatividad (puede inventar detalles)
- dec_w = 0.5 → equilibrio
- dec_w = 1.0 → máxima fidelidad al input original
Para imágenes médicas se recomienda dec_w alto (0.7-1.0) para no inventar estructuras.

## 6. ESTRUCTURA DE EXPERIMENTOS (ABLATION STUDY)

El profesor pidió explícitamente (correo):
"comparativa usando algún modelo de difusión preentrenado de Hugging Face,
comparando planificadores de ruido y técnicas de generación estocásticas vs. deterministas"

Las fases acordadas, cada una responde una pregunta:

FASE 1 — ¿Mejora el fine-tuning?
  - StableSR sin fine-tuning (inferencia pura con pesos oficiales)
  - vs StableSR con fine-tuning del Time-aware Encoder + CFW
  - Dataset de fine-tuning: pares sintéticos (imagen_original, imagen_degradada)
    generados desde las 40 imágenes de train de cada fold

FASE 2 — ¿Mejora el data augmentation en el fine-tuning?
  - Fine-tuning sin augmentation
  - vs fine-tuning con augmentation (flips H/V, rotaciones 90°, variación de brillo)
  - Augmentations específicas para microscopia: NO usar cambios de color agresivos

FASE 3 — Mejor planificador de ruido
  - DDIM (determinista)
  - PNDM
  - LMSDiscrete
  Comparar con mismos pasos (50) para aislar efecto del scheduler

FASE 4 — Mejor número de inference steps
  - 25 / 50 / 100 / 200 pasos
  - Con el mejor scheduler de la Fase 3
  - Analizar trade-off calidad vs tiempo de cómputo

FASE 5 — Estocástico vs determinista
  - DDPM (estocástico, cada run da resultado distinto)
  - vs DDIM (determinista, misma semilla = mismo resultado)
  - Relevante para reproducibilidad científica

FASE 6 — Mejor loss function (solo si se hace fine-tuning)
  - L1 loss
  - L2 loss (MSE)
  - Perceptual loss (LPIPS/VGG)
  Cambiar en: ldm/models/diffusion/ddpm.py función p_losses()

Orden recomendado de ejecución:
Fase 1 → Fase 2 → Fase 6 → Fase 3 → Fase 4/5
(primero optimizar el modelo, luego el proceso de sampling)

## 7. MÉTRICAS

Para evaluar calidad de imagen (modelos de difusión, NO requieren ground truth):
- BRISQUE: menor = mejor (evalúa artefactos y naturalidad)
- NIQE: menor = mejor (calidad sin referencia)

Para evaluar calidad de imagen (SI hubiera ground truth):
- PSNR: mayor = mejor
- SSIM: mayor = mejor (0-1)
- LPIPS: menor = mejor (calidad perceptual)

Para evaluar YOLO (métricas principales del TFG):
- mAP@50: métrica principal de comparación con el paper
- mAP@50:95: métrica secundaria más estricta
- Precision y Recall por clase

ADVERTENCIA IMPORTANTE:
Un modelo que mejora BRISQUE/NIQE puede empeorar mAP de YOLO.
Esto no es un fracaso — es un resultado válido que indica que las métricas de calidad
perceptual general no predicen bien el rendimiento en detección de objetos médicos.
Es una conclusión académica relevante para el TFM.



## 8. DATASET DE FINE-TUNING PARA STABLESR

Problema: StableSR necesita pares (imagen_degradada, imagen_original) para fine-tuning.
No tenemos versiones de alta calidad de nuestras imágenes.

Solución: degradación sintética sobre las imágenes originales.
Las imágenes originales actúan como ground truth.
Las versiones degradadas sintéticamente son el input.

Código de degradación sintética:
```python
from PIL import Image, ImageFilter
import numpy as np

def degrade_image(img):
    # Blur gaussiano (simula desenfoque del microscopio)
    img = img.filter(ImageFilter.GaussianBlur(radius=2))
    # Ruido gaussiano (simula ruido del sensor)
    arr = np.array(img).astype(np.float32)
    noise = np.random.normal(0, 15, arr.shape)
    arr = np.clip(arr + noise, 0, 255).astype(np.uint8)
    return Image.fromarray(arr)

# Par de entrenamiento: (degrade_image(img_original), img_original)
```

Tipo de degradación a usar: bsrgan pipeline (ya implementado en StableSR)
o degradación manual como la anterior.

## 12. NOTAS CONCEPTUALES IMPORTANTES

- YOLO es discriminativo: aprende a clasificar → necesita fine-tuning, k-fold, labels
- StableSR es generativo: aprende a transformar → no necesita k-fold, no tiene riesgo
  de overfitting en inferencia de la misma manera

- K-fold es para YOLO únicamente, no para StableSR

- Data augmentation del fine-tuning de StableSR: flips y rotaciones tienen sentido
  para microscopia. Cambios de color agresivos NO (imágenes Giemsa tienen colorimetría
  diagnósticamente relevante, aunque las imágenes sean en escala de grises)

- Con 8GB VRAM: usar batch_size=1, fp16=true, gradient_checkpointing si disponible
